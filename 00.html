01 / Need

What needed solving?

The main problem was simple:How can a mobile robot move from one level to another using stairs while remaining stable and controllable?
A normal four-wheel arrangement cannot simply drive up a staircase because the wheels cannot continuously maintain the required contact with the stair surfaces.

02 / Decision

Why this approach?

The project explored a mechanical climbing mechanism where the robot does more than simply rotate its wheels.
The mechanism must:
Support the robot's weight.
Lift the robot to the next step.
Move the robot forward.
Maintain balance during lifting.
Return to a stable position before the next climbing cycle.
This makes the project both a mechanical design problem and a control problem.

03 / Result

What works now?

The working concept is based on coordinating the drive system, lifting mechanism, and control sequence.
Instead of trying to force the wheels to climb the stair directly, the mechanism helps reposition the robot onto the next step.

01

Problem definition

The problem I wanted to solve was not simply:
"I need a calculator."
It was: "I need a tool that can help me understand and solve mathematical, physics and chemistry problems by connecting formulas, known quantities and unknown quantities."
A normal calculator can calculate numbers. But when solving a physics problem, the difficult part can be knowing:
- Which formula should I use?
- What quantities do I need?.
- Which quantities do I already know?
- Which quantity am I trying to find?
- Are there multiple formulas that can give me the same quantity?
- What happens if I do not know one of the required variables?
I wanted the KJC Calculator to address these questions.

03

Research and investigation

At the time, I was still learning programming myself.
My main learning source was online material, particularly YouTube.
I learned Python and eventually discovered Tkinter for creating graphical interfaces.
The important innovation in my idea was not simply making another calculator.It was the way I wanted the calculator to connect:
Formula + Variables + User Input + Calculation + Learning
Instead of forcing the user to already know the formula, the calculator could help expose the available formulas. Instead of requiring every variable to be entered, the system could determine what was missing. This turned the idea from a simple calculator into something closer to a formula-based problem-solving tool.

The planned KJC Calculator could be viewed as several connected layers.
User Interface Built using Python and Tkinter. This would contain:
- calculator interface
- tabs
- subject sections
- formula sections
- input fields
- buttons
- result displays
Formula Database
A collection of formulas organised according to subject and topic. For example: Physics → Motion → Speed

Input System
The user enters the values they know. Unknown quantities can remain empty.
Calculation Engine
The calculation engine determines how to use the selected formula and calculate the required quantity.
Output

Learning/Reference Section
The long-term idea included having formulas stored inside the application so that the calculator could also act as a reference.

05

Concept development

The concept developed through several iterations. Initially, the idea was simply to create a calculator. Then I started thinking: What if it contained formulas? Then: What if I could select the quantity I wanted to find? Then: What if it could show me all the formulas that could help me find that quantity? Then: What if I only entered the values I knew and the program figured out the unknown?
This progression made the project increasingly ambitious. The calculator therefore evolved from a simple mathematical tool into a proposed multi-subject computational and learning platform.

06

Detailed design and modelling

The application was developed using Python and Tkinter. I created the graphical interface and developed multiple iterations of the application. The interface was one of the parts that successfully developed. The main window could open, different tabs or sections could be accessed, and the calculator functions could perform calculations. The challenge was not primarily creating the interface. The bigger challenge was developing the logic behind the flexible formula system. A simple calculation can be represented as:
Known values → Formula → Answer
But the system I wanted required something more like:
Desired quantity → Possible formulas → Available variables → Determine suitable equation → Calculate unknown → Display result
That required much more complex logic.

07

Calculation logic

This was the most challenging part of the project. Consider the problem of finding speed. A simple implementation could use:
Speed = Distance / Time
That is straightforward when distance and time are known. But I wanted the system to support many possible relationships.
The calculator therefore had to understand:
- what quantity the user wanted
- which variables were available
- which variables were missing
- which formulas could be used
- whether the available information was sufficient
- which calculation should be performed
The same concept was intended to work throughout the application. This created a much larger programming problem than simply writing individual formulas.

08

Prototype and testing

I created several iterations of the KJC Calculator. The interface itself reached a working state.
I was able to:
- open the application
- navigate the interface
- access tabs/sections
- enter values
- perform calculations
- receive results
This showed that the basic software architecture and graphical interface were working.
The difficulty appeared when I attempted to make the formula system flexible enough to handle many different combinations of known and unknown variables.

09

Failure analysis and iteration

The main limitation appeared when I moved from restricted calculations to generalised calculations. If I limited the system to a small number of known parameters, it was manageable. For example: Distance + Time → Speed works clearly. But I wanted the calculator to handle many possible combinations automatically. That meant the program needed to understand relationships between multiple variables rather than simply execute a fixed formula. As the number of possible combinations increased, the calculation logic became increasingly difficult to manage. Some iterations reached the same limitation. The interface continued to work, but the complete calculation engine I envisioned was not finished. Eventually, I paused the project.

10

Validation and final evalution

The KJC Calculator was therefore partially successful.
What worked
- Python application development
- Tkinter graphical interface
- Main application window
- Tabs and sections
- Calculator functions
- Numerical calculations
- Multiple iterations
- Basic formula-based calculations
What remained unfinished
- Fully flexible formula selection
- Automatic handling of every possible combination of known and - unknown variables
- Complete mathematics, physics and chemistry formula library
- Full intelligent calculation engine
- Complete educational/reference-book functionality
The important point is that the project was not simply a failure. The software foundation worked, but the complete vision was more complex than I was able to implement at that stage.

11

Engineering lessons

The KJC Calculator taught me an important lesson about software development:A working interface does not necessarily mean the underlying system is complete.
I learned that creating buttons, windows and basic calculations can be relatively straightforward. The difficult part is designing the logic that allows all those components to work together reliably. I also learned that the complexity of a system can increase very quickly when you move from a fixed solution to a general solution.
A calculator that performs: A + B = C is simple.
A calculator that understands: "I want C, I know A, I don't know B, and there are several possible relationships between these quantities" is a much different engineering problem. That difference became very clear through this project.

12

Documentation and next iteration

The KJC Calculator is currently paused rather than abandoned. The original idea is still valuable to me because it came from a genuine problem I wanted to solve for myself. With the programming knowledge I have gained since then, and with modern AI-assisted development, I believe I can approach the project differently when I return to it. The next version could be designed around a more structured formula engine rather than trying to build all the calculation possibilities at once.
The long-term vision remains: Mathematics + Physics + Chemistry + Formula Library + Calculation Engine + Learning Tool
in one application.
