01 / Overview

Give the audience the reason first.

A strong project conversation does not begin with a list of tools. It begins with the need, the people affected, and the outcome you wanted to create.

The challenge is simple to state. The solution is not.

The project was developed to create a mobile robot capable of moving across different floor levels without relying on conventional elevators or ramps.
Normal wheeled robots work well on flat surfaces, but stairs create a major mobility problem. A robot designed only for flat-ground movement can lose contact, become unstable, or tip over when it encounters a step.
The aim was therefore to develop a stair-climbing mechanism that can lift, support, and reposition the robot while maintaining stability.

02 / The story

Make the thinking easy to follow.

Use these three beats to keep the discussion focused: what happened, what you decided, and what changed because of the work.

01 / Need

What needed solving?

The main problem was simple:How can a mobile robot move from one level to another using stairs while remaining stable and controllable?
A normal four-wheel arrangement cannot simply drive up a staircase because the wheels cannot continuously maintain the required contact with the stair surfaces.

02 / Decision

Why this approach?

The project explored a mechanical climbing mechanism where the robot does more than simply rotate its wheels.
The mechanism must:
Support the robot's weight.
Lift the robot to the next step.
Move the robot forward.
Maintain balance during lifting.
Return to a stable position before the next climbing cycle.
This makes the project both a mechanical design problem and a control problem.

03 / Result

What works now?

The working concept is based on coordinating the drive system, lifting mechanism, and control sequence.
Instead of trying to force the wheels to climb the stair directly, the mechanism helps reposition the robot onto the next step.

03 / Process

From problem to working system.

Document the engineering process in the order it actually happened: define the problem, establish requirements, develop and analyse concepts, build prototypes, test against measurable criteria, iterate from evidence, and record the final outcome.

01

Problem definition

The first step was to define the mobility problem.
The robot needed to:
- Detect/approach a stair.
- Position itself correctly.
- Lift or reposition its body.
- Move onto the next step.
- Stabilize itself.
- Repeat the sequence until the staircase is completed.
The major engineering challenge was maintaining stability while the robot's center of gravity changes during climbing.

02

Requirements and constraints

The design requirements included:
- Ability to climb stairs.
- Stable movement.
- Sufficient lifting force.
- Controlled motor movement.
- Controlled servo/mechanical movement.
- Compact mechanical structure.
- Reasonable weight.
- Strong enough frame.
- Safe operation.
- Repeatable climbing sequence.
Important constraints included:
- Motor torque.
- Servo torque.
- Robot weight.
- Stair height.
- Stair depth.
- Available space for the mechanism.
- Battery capacity.
- Material strength.
- Manufacturing limitations.

03

Research and investigation

Different stair-climbing approaches were investigated, including:
- Wheel-based systems.
- Tracked systems.
- Legged mechanisms.
- Triangular wheel arrangements.
- Articulated mechanisms.
- Lifting mechanisms.
The research helped identify what each approach does well and where it becomes difficult.
The important question was not simply: "Which mechanism can climb stairs?"
but: "Which mechanism can climb the required stairs using the components, manufacturing methods, and control system available to us?"

05

Concept development

Several concepts can be considered before selecting the final mechanism.
Each concept is evaluated based on:
- Stability
- Complexity
- Cost
- Manufacturability
- Weight
- Torque requirements
- Control difficulty
- Stair dimensions
The selected concept should provide the best balance between these requirements.

06

Detailed design and modelling

The mechanical structure was then developed in SolidWorks.
The modeling stage involved:
- Creating the robot frame.
- Designing the lifting mechanism.
- Positioning the motors.
- Designing servo mounting points.
- Designing wheel locations.
- Checking clearances.
- Checking mechanical interference.
- Estimating the center of gravity.
- Preparing components for fabrication.
This stage allowed mechanical problems to be identified before building the physical prototype.

07

Simulation and analysis

Before fabrication, the design can be analyzed to determine whether it can withstand the expected loads.
Important calculations include:
Motor torque
T = F * r
where:
T = required torque
F = required force
r = effective wheel/mechanism radius
For the lifting mechanism, the robot's weight creates a moment around the mechanism:
M = W * d
where:
W = robot weight
d = perpendicular distance from the pivot.
The simulation and calculations help answer:
Can the mechanism physically lift and support the robot?

08

Prototype and fabrication

After the design was finalized, the components were fabricated and assembled.
This stage revealed an important engineering reality:
A design that works in CAD does not automatically work perfectly in the physical world.
Manufacturing tolerances, friction, material flexibility, screw alignment, motor positioning, and assembly errors can all affect performance.

09

Subsystem testing

Instead of testing the complete robot immediately, individual subsystems were tested first.
For example:
Motor system
- Forward
- Reverse
- Left
- Right
- Stop
Servo system
- Starting position
- Lifting position
- Returning position
Sensor system
- Distance measurement
- Obstacle detection
Power system
- Voltage levels
- Current requirements
- Servo supply
- Motor supply
This makes troubleshooting much easier.

10

Integration and system testing

Once the individual subsystems worked, they were integrated.
The complete sequence could then be tested:
Approach → Detect → Position → Lift → Move → Stabilize → Repeat
This is where problems that do not appear during individual subsystem testing can become visible.
For example, a servo may work perfectly by itself but struggle when carrying the actual robot load.

11

Failure analysis and iteration

Failures are not simply problems; they provide engineering information.
Possible failures include:
- Insufficient motor torque.
- Servo struggling under load.
- Robot losing balance.
- Wheels slipping.
- Mechanism binding.
- Frame deformation.
- Incorrect timing between motors and servos.
- Sensor giving unreliable readings.
- Robot stopping at the wrong position.
Each failure leads to a question:
Why did it happen?
Then:
Failure → Cause → Modification → Retest
This cycle is one of the most important parts of the project

12

Validation and final evaluation

The final design should be tested against the original requirements.
For example:
Requirement Test

Climb stairs Complete multiple stair cycles
Maintain stability Observe robot during lifting
Lift robot Measure/verify lifting capability
Detect obstacle Test ultrasonic response
Repeat operation Perform multiple cycles
Safe operation Check emergency/stop behavior
The goal is not simply to show that the robot moves.
The goal is to demonstrate that it meets the engineering requirements that were defined at the beginning.

13

Engineering lessons

The stair-climbing robot demonstrates several important engineering lessons:
- Design starts with the problem, not the component.
- CAD is important, but physical testing is essential.
- Mechanical design and electronics must be developed together.
- Torque requirements must be calculated before selecting actuators.
- Stability is as important as movement.
- Subsystem testing makes troubleshooting easier.
- Failure is part of the engineering process.
- Small mechanical changes can have a major effect on system performance.
- A successful prototype is the result of repeated design → build → test → improve cycles.

14

Documentation and next iteration

The final stage is documenting: - Original problem. - Design requirements. - Research. - Concepts considered. - Selected concept. - CAD models. - Calculations. - Simulation results. - Fabrication process. - Circuit/control system. - Testing results. - Failures. - Modifications. - Final performance. - Lessons learned. The next iteration can then focus on improvements such as greater stability, higher climbing speed, better weight distribution, improved sensing, stronger mechanical components, and more autonomous control.

# defining the speak function
def speak(things):
    Speaker.say(things)
    Speaker.runAndWait()
    pass

# test ting the speak function
speak('Welcome in KJC')
speak('Please, Choose your file!')
# file path and name through the gui
file = filedialog.askopenfilename()



# create a pdf file object
pdfFileObj = open(file, "rb")

# create a pdf reader object
pdfReader = PyPDF2.PdfFileReader(pdfFileObj)

# pages of the pdf file
pages = pdfReader.numPages

# where do you want to start
speak("Where do you wish to start")
begin = int(input('Where do you wish to start : '))


# create pdfplumber object and loop through the number of pages in pdf
with pdfplumber.open(file) as pdf:
    # loop through the number fo pages
    for i in range(begin-1, pages):
        print("\n \nPage " + str(i + 1) + "/" + str(pages) + "\n\n")
        page = pdf.pages[i]
        text = page.extract_text()
        print(text, "\n")
        speak(text)
